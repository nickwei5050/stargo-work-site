# Capability map — 用 cinery 手风琴重建（2026-09-07）

## 为什么换掉上一版

上一版我从 qubix 里挑了 `.service-details-rice`——那是整个模板里**唯一一个完全没有动效**的静态区块（标签 + 富文本）。结构对，但做出来不炫酷，是选型错误。

## 四个模板的实地评估

四个模板都在浏览器里跑过，不是看截图或类名猜的。

| 模板 | 动效基础 | 结论 |
|---|---|---|
| **cinery** | GSAP + ScrollTrigger + SplitText；FAQ 手风琴由 Webflow IX2 驱动 | **选用**。金属渐变拆分大标题 + 计数器 + 深色圆角行点击展开、加号旋转。无需图片，深底与能力页一致 |
| lumenis | GSAP + Observer（拖拽/无限滚动） | 服务卡结构好（编号 + 大标题 + ⊕ 子项），但每卡需要一张人像大图 |
| qubix | GSAP + ScrollTrigger | 跑马灯、滚动进度条可作点缀；服务详情块无动效 |
| renok | 自有 radiant-vault.js，**无 GSAP**；「10 个 tab」实为 `rt-tab-display-off` 响应式显示类，不是 tab 组件 | 不用。服务区浅底 + 人像，与深色能力页冲突 |

## 移植了什么

`tools/cinery-prepare.mjs`（新增）从 `tools/templates/cinery/` 抽取：

1. **标记**：FAQ 标题块 + 一个手风琴行（作为重复单元），从捐赠页原样切出，不手写。
2. **命名空间**：12 + 9 个类全部加 `cn-` 前缀。cinery 的 `.subtitle`、`.title-wrapper`、`.section-number` 与 Mono/Scalora/Lifelogx 重名，不加前缀会重绘全站。脚本带断言：有未加前缀的类就构建失败（实际抓到了漏掉的 `top-title`/`bottom-title`）。
3. **样式**：46 条规则 + 捐赠模板的 115 个 `:root` 自定义属性。**变量是关键**——`background-color: var(--primary-color--dark)` 之类占了绝大多数，不带变量整块会渲染成黑底黑字（第一次就是这样）。全部作用域在 `.cn-capmap` 下。
4. **交互**：4 个 IX2 事件（点击 / 再次点击 / 悬停进出）+ 4 个动作列表，类选择器同步改名，id 加前缀，页面 id 重映射到我们的。经 `tools/fuse-ix.mjs` 并入 `js/app.fused.js`（与 Lifelogx 同一套机制）。

动作列表用的是 `CHILDREN` + 类选择器（`.cn-accordion-content-wrap`、`.cn-plus-line.cn-vertical`），所以 24 行共用一个 `data-w-id` 时各自独立展开——与捐赠模板 5 行的行为一致。

## 模块结构

24 个手风琴行，分三段：

- **6 个业务成果**（Find the buyers worth pursuing 等），每行展开是：业务说明 → 相关能力（粗体名 + 说明）→ Useful output → Connects to → 归属能力组
- **4 个共同基础**（业务上下文 / 工具与连接 / 权限与证据 / 可核查的改进）
- **14 个能力组目录**，每组展开是该组全部能力

标题 `EVERY / JOB`，眉标 `CAPABILITY MAP`，计数器 `(14)`。

**防脱节**：故事里每个能力名在构建时到 `CAPABILITY_GROUPS` 查表，打印的是登记表自己的说明。叙事与目录不可能给出不同描述；能力改名会让构建失败而不是从页面消失。

## 保留

`#atlas` 与 `#g01`–`#g14` 锚点全部保留；上方九阶段 loop 表、页头、hero、页脚、其他路由未动；**中文能力页仍是原表格**（中文页不在本轮范围）。

## 两处因内容而非口味的调整

1. **标题用词**：捐赠模板的 192px 大字是给 "Quick"/"Answers" 这种 ≤7 字母的词设计的。"Connected"(1216px) 与 "Capabilities"(1319px) 都超过 1180px 的列宽，"Capability" 在 768–991 区间也超。实测后改用 `EVERY / JOB`。
2. **响应式档位**：捐赠模板的标题是 192/160/128/96/56px 五档，但只有前两档在移植脚本能读到的 media 块里，其余嵌套更深。逐宽度测量捐赠页后补齐，缩放行为与原版一致。

## 同一轮修的其他问题

| 问题 | 根因 | 处理 |
|---|---|---|
| 定价页字体变了 | 我为 qubix 模块加的 `@font-face` 让 Scalora 一直声明但从未加载的 InterDisplay 真的加载了，全站 Scalora 页面换了字 | qubix 块已废弃，连同 `@font-face` 与 `assets/qubix/` 一并删除 |
| 定价页强调词变形 | `.sub-title-text` 用 Instrument Serif 斜体，拉丁斜体衬线无 CJK 字形，浏览器合成倾斜 | 让它继承标题字体，用洋红渐变区分 |
| 定价页残留橙色 | Scalora 把几个强调色写成字面十六进制（12% 透明度）而非走 token | 6 处重绑为洋红。中英定价页橙色命中now 0 |
| 定价页标题要渐变 | — | 用遮罩实现向下渐隐。**不能用 `background-clip:text`**：标题被 SplitText 拆成逐字 span，渐变在 h1 上而字形在 span 里，文字会整体消失（试过，只剩一个「级」） |
| 智能层「不再/等提示」偏左 | 词与手机共用一个栅格，左边距比右边距一直小 64px | 整组右移 32px，三个宽度下左右边距完全相等 |
| 博客配图不对 | 封面用的是 Mono 模板的产品摄影（耳机、红底工具），与文章内容无关 | 换成自有编辑图：`os-quote-studio` 对询盘到报价、`brand-ontology` 对企业本体、`os-agent-center` 对 288 AI 员工等。自有素材，无第三方授权问题 |
| 能力说明仍复述功能名 | 上一轮按词序与长度复查发现 20 条词序变体 + 42 条过短 | 全部重写。157 条中复述 0、过短 0 |

## 实际跑过的检查

- 手风琴交互实测：关闭 0px → 展开 907px，加号旋转，无 JS 错误
- 标题在 320/390/768/991/1024/1280/1440/1920 八个宽度：无溢出、无横向滚动
- 锚点：点击 `#g07` 到位，深链 `#g12` 落点顶边 0
- 七个回归套件
- **未做**：真实设备、Safari/Firefox、无障碍审计、线上验证（未部署）

## 中文页同步（业主已批准）

中文能力页现在用同一个模块，同样的动效。

- `CAPABILITY_SHOWCASE` 的 49 个文本字段全部改为 `B(zh, en)`；生成器里每处文本都走 `t()`。
- 标题中文用 `每一项 / 工作`，对应英文的 `EVERY / JOB`。捐赠模板的单行槽位在 1440 时是 1180px，三个中文字约 576px，390 时约 168px 对 346px——每个宽度都放得下，实测无溢出。
- **157 条中文说明全部重写**。原来基本是功能名直译（报价工作室 之于 Quote Studio），和英文改造前一样；现在讲的是这项能力做什么，例如 报价从询盘开始，不从空表格开始、推断哪些进口商可能到了补货窗口。顺带修了两条仍在复述自己的英文说明（Command Center、Mobile Companion）。
- 中英两页结构一致：各 24 个手风琴行、14 个分组锚点、250 条能力行。
